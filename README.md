# 低功耗设备仿真系统

纯 Go 的事件驱动仿真：在一条确定性时间线上对处理器、外设和唤醒事件建模，
首轮覆盖**休眠进入、唤醒恢复、能耗累计**。无需任何硬件，后续增加设备类型只需
复用 `sim.Timeline` 并接入 `sim.Meter`。

## 运行

```bash
go test ./...          # 全部规则与对账测试
go run ./cmd/simdemo   # 周期采样 + 突发事件的演示
```

## 模型

- `sim/timeline.go`：通用最小堆时间线，时间单位纳秒；设备模型只是其中的事件，
  新设备类型可直接复用，不需要改动内核。
- `sim/processor.go`：处理器四态机
  `active -> entering-sleep -> asleep -> waking -> active`。
  休眠进入与唤醒恢复都有独立耗时和功耗，全部计入时间与能量账；恢复进行中再到
  唤醒原因不会启动第二次恢复，但原因全部保留，激活时一次性交付。
- `sim/peripheral.go`：传感器/射频等外设。`RequestOff` 遇到未完成传输时只登记
  关机意图，外设继续供电；最后一次 `FinishTransfer` 后才真正断电，因此绝不可能
  在传输途中被关掉。
- `sim/energy.go`：能量计。功率用 mW、时间用 ns，乘积即 pJ，整数积分无误差；
  每次状态变化前结账并记录恒功率段，可用段轨迹独立重算能量来对账。
- `sim/device.go`：把处理器、传感器、射频和唤醒仲裁器组装为一个设备。一次恢复
  服务全部并发原因（每个原因都是一份工作量），活跃期到达的原因直接追加工作而不
  再次恢复。作业生命周期覆盖转换+射频传输，保证“先完成传输、再关外设、再休眠”。
- `sim/scenario.go`：周期采样 + 突发唤醒场景编排，以及状态快照/恢复
  （`TakeSnapshot` / `Restore`）。快照只允许在处理器已休眠且无传输在途的稳定点
  生成；从快照续演必须与一次跑完在时间、工作量、唤醒次数和能量上完全一致。

## 演示场景（100ms）

- 每 10ms 一次周期采样（2ms 转换 + 1ms 射频发送）。
- 10.1ms 的突发落在采样会话内：不重复恢复，但计入工作量并保留原因。
- 35.06ms / 35.07ms 两个突发在同一次恢复中合并为一次，原因保留两条。
- 在 19ms 保存状态后续演，结果与全程演练逐项对齐。
